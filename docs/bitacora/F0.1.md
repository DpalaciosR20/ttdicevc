## 3. Método

### 3.1 Diseño

El código del repositorio (`src/generation/compute_checksums.py`, líneas 1–17 y 43–79) define el siguiente procedimiento:

1. Recorre, para cada técnica, `data/images/<carpeta>/**/*.png`.
2. Valida el nombre de cada archivo contra la expresión `^(perlin|lorenz|rd)_<tag>_<idx:4>_label<n>.png`.
3. Exige 1,136 imágenes por técnica (`N_PER_TECH = 1136`, línea 32).
4. Escribe `data/images/checksums.csv` con las columnas `technique, split, idx, label, relpath, sha256`.
5. Escribe `data/images/checksums_env.json` con las versiones del entorno.

El docstring (líneas 6–8) indica que el script debe ejecutarse «SOLO después de que tests/test_label_independence.py pase la capa C (test_C_reproduccion_desde_u)».

## 10. Texto para el reporte técnico

El código de los tres generadores de imágenes analíticas (flujos de ruido de Perlin, atractor de Lorenz y reacción-difusión de Gray-Scott) se consolidó en el repositorio del proyecto junto con un procedimiento para calcular sumas SHA-256 de las imágenes generadas. La integridad del conjunto de 3,408 imágenes (1,136 por técnica) se registra en el manifiesto de datos del proyecto, que asocia a cada archivo su suma SHA-256 y a cada técnica un resumen agregado.

Una verificación posterior recalculó las sumas de todas las imágenes almacenadas y las comparó con las del manifiesto. Las 3,408 coincidieron, sin archivos faltantes ni sobrantes en ninguna de las tres técnicas. Esta verificación garantiza la integridad de los artefactos empleados en el entrenamiento, pero no su reproducción a partir de los componentes UMAP, que se verificó por separado mediante la prueba de independencia de etiqueta.
